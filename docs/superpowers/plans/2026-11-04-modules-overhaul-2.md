# Modules overhaul 2 — polish, types, labels, module list, sprints

Continues docs/superpowers/plans/2026-11-03-modules-overhaul.md (all four phases + issue-style pages are committed). Same conventions: dev phase, edit EXISTING migrations in place (no new migration files), `migrate:fresh --seed` then `db:seed --class=DemoSeeder`, Pest + real-browser (Playwright under the scratchpad `pw` folder) verification, never commit unless the user says so, kill only the dev server you started.

## Decisions (made with the user)
- **Icons**: copy only the icons we use (no library install) from Lucide (ISC) as the single source, Heroicons (MIT) only for an icon Lucide lacks. One folder of SVG files + `<x-icon name="pencil" class="h-4 w-4"/>` (reads the file, cached; strokes use currentColor). Add a licence notice file. Types and labels get ONE optional `icon` field holding either an icon name from the curated set or a pasted emoji (plain text, escaped); the picker shows the icon grid plus an "or type an emoji" box. Icon-only buttons need `title` + `aria-label`. Apply first to: module/task/subtask pages ("…" menus, edit pencils, add links, convert/copy), Modules tab, Board, Sprint tab, type/label pickers; drag handle on every reorderable list. Other pages gradually later.
- **Description cards (GitHub style)**: each description and comment card has a "…" menu: Copy link, Copy Markdown, Quote reply (comments), Edit (opens the in-place editor), and shows "Last edited by …". Top-right of task page: "New task" button (creates a task in the same module) and a copy-link icon.
- **Progress rule (task)**: steps = checklist items + subtasks + 1 extra "moved to Done" step. done = ticked items + done subtasks + (1 if the task is in a done-stage column). A task in a done-stage column is 100% regardless. No items and not done = 0%. Example: 2 checklist items both ticked, not in Done = 2/3 = 66%. Module progress = hours-weighted average of task progress using the SAME rule; remove the second competing calculation (Module::progress vs ProgressService::forModule) so the module bar and task bars agree. Derived module status is unchanged.
- **Colours**: stage badges Not started grey, Active blue, Review amber, Done green; completed modules and 100% bars green; priority Low grey, Medium amber, High red (tasks and modules); deadline yellow when 0–3 days left (including today and tomorrow), red when past and not done, no warning when done.
- **Task dates**: tasks get `started_at` (set the first time the task enters an Active-stage column) and `completed_at` (set on entering a Done-stage column, cleared when it leaves); both editable by hand; show in the task sidebar with "took N days". Modules show derived start/end. Column moves are already in the activity timeline.
- **Subtasks**: "+ Add subtask" is a link that opens the input (not open by default). Subtasks have no type. Convert-to-task asks for a task type (default Task).
- **Checklist**: Checklist section on task and subtask pages using the existing checklist feature (ChecklistItem morph, Checklist\Panel); markdown `- [ ]` items in descriptions become clickable (toggle updates the stored markdown). Checklist items, subtasks and module-list tasks are draggable (SortableJS is installed) to reorder. Tasks use ONE order per module (`tasks.position` = priority rank); the board shows tasks within each column in that same order and a board drag recomputes the relevant positions.
- **Task types** (dynamic): `task_types` table (name, color, icon nullable, position, is_system), `tasks.task_type_id` FK nullable. Seeded defaults: Task, Issue, Feature, Bug, Change. Edit freely; a type in use cannot be deleted without picking a replacement. Shown as a coloured badge with icon on task page, board cards, lists, sprint rows; selectable in task form/page sidebar and copy/convert. Only the super admin creates/edits/deletes types, via a management page; everyone else can only assign.
- **Labels**: add optional `icon`; seed defaults (Urgent, Blocked, Needs review, Design, Frontend, Backend, Documentation, Question) with colours. Only the super admin creates/edits/deletes labels (management page); remove the inline "new label" box for others on module and task pages (they can still assign existing labels).
- **Module list** (`projects/{id}?tab=modules`): assignee picker on each module row; module `priority` (Low/Medium/High) and drag-to-reorder (top = highest priority; `modules.position`); filters Sprint / Backlog / Completed plus a user filter (Sprint = modules having tasks in the active sprint; Backlog = modules with no tasks in the active sprint and not completed; Completed = completed); completed modules (derived or manual completed) move out of the main list into a collapsed section at the bottom "Completed (N)", closed by default.
- **Sprint tab** (after Modules, per project, ONE active sprint at a time): `sprints` (project_id, name, goal, starts_on, ends_on, status planned|active|completed, completed_at); `tasks.sprint_id` nullable (a task is in at most one sprint). Plan view: three lists Active sprint / Next sprint(s) / Backlog (project tasks not done, not in a sprint), drag tasks between lists and up/down; list headers show task count and total estimate hours; rows show assignee, type icon, labels, priority; filter by user, type, label. Board view: the existing board columns restricted to the active sprint's tasks with a sprint header (name, dates, days left, goal, done/total progress). Starting a sprint offers 1 or 2 weeks (dates filled from today, editable). "Complete sprint" shows done/unfinished counts; unfinished tasks go to the next sprint or the backlog (user's choice); done tasks stay with the completed sprint; short summary planned vs done hours. Board tab gets an "Active sprint / All" switch. Burndown/velocity and a cross-project "My week" view are later.
